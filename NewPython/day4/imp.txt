Why Two Different Routes in Flask (GET vs POST)

1. GET Route: Shows the form
--------------------------------
When the user visits /register, the browser sends a GET request.

GET is used for:
- showing pages
- retrieving information
- NOT modifying data

Example:
@app.get("/register")
def show_form():
    return render_template("register.html")

This simply displays the HTML form.

2. POST Route: Handles form submissions
-----------------------------------------
When the user submits the form, the browser sends a POST request.

POST is used for:
- sending data to the server
- creating or modifying data
- receiving form data in request.form

Example:
@app.post("/register")
def register():
    name = request.form.get("name")
    age = request.form.get("age")
    return f"Received: {name}, Age: {age}"

3. Why not use one route?
----------------------------
You *can* combine GET and POST into one function:

@app.route("/register", methods=["GET", "POST"])
def register():
    if request.method == "GET":
        return render_template("register.html")
    if request.method == "POST":
        name = request.form.get("name")
        age = request.form.get("age")
        return f"Received: {name}, Age: {age}"

This works, but mixing logic for GET + POST can make code harder to read and maintain.

4. Summary
-----------
GET  -> shows the form (read-only)
POST -> processes submitted data (write)

Separating them keeps the logic clean and organized.

Different Ways to Get Form Data in Flask

1. request.form["field"] (Dictionary-style access)
-------------------------------------------------
Example:
    name = request.form["name"]
    age = request.form["age"]

Pros:
- Direct access like a normal dictionary.
- Use when you are sure the field always exists.

Cons:
- Raises KeyError if the field is missing.
- Not safe for optional fields.

Use only when the form always sends the value.


2. request.form.get("field") (Most common method)
-------------------------------------------------
Example:
    name = request.form.get("name")
    age = request.form.get("age")

Pros:
- Safe: returns None if the field does not exist.
- Does not throw an error.

Cons:
- You must manually check for None if needed.

This is the recommended default way.


3. request.form.get("field", default_value)
--------------------------------------------
Example:
    name = request.form.get("name", "")
    age = request.form.get("age", 0)

Pros:
- Safe, with a fallback value.
- Useful when you want guaranteed defaults.


4. request.values.get("field") (GET + POST combined)
-----------------------------------------------------
Example:
    name = request.values.get("name")
    age = request.values.get("age")

Pros:
- Works with both:
    - GET parameters (?name=...)
    - POST form data

Cons:
- Hard to tell whether data came from GET or POST.

Use when the data source doesn’t matter.


5. Access all fields at once
-----------------------------
Example:
    form_data = request.form.to_dict()
    print(form_data)

Or:
    for key, value in request.form.items():
        print(key, value)

Pros:
- Useful for debugging.
- Perfect for dynamic forms or when you don’t want to extract each field manually.


Summary Table
--------------
Method                          | Returns error?      | Notes
------------------------------- | ------------------- | -------------------------------
request.form["name"]           | Yes (KeyError)      | Use only if field always exists
request.form.get("name")       | No                  | Safest and most common
request.form.get("name", def)  | No                  | Provides a fallback value
request.values.get("name")     | No                  | Works for both GET and POST
request.form.to_dict()         | No                  | Retrieves all form data at once

What does form_data = request.form.to_dict() do?

1. request.form is not a normal dictionary.
   It is a MultiDict, which can store multiple values for the same key.

2. Calling .to_dict() converts the MultiDict into a regular Python dictionary.
   This makes it easier to work with in Python.

Example:
If a form submits:
  name = "John"
  age  = "25"
  email = "john@example.com"

Then:
    form_data = request.form.to_dict()
    print(form_data)

Output:
{
    "name": "John",
    "age": "25",
    "email": "john@example.com"
}

3. Why use to_dict()?
- To easily see all submitted form data at once.
- Useful for printing, debugging, or saving the form data.
- Allows you to process the data without manually accessing each field.

4. Common uses:
- print(form_data) to debug
- Pass entire form to templates
- Save all form fields into a database
- Avoid typing request.form.get() for every field

Flask Flash Messages (Show Errors Inside HTML)

1. What are flash messages?
---------------------------
Flash messages allow you to temporarily store a message (error, success, warning)
and display it on the next page. They are used for:
- Form validation errors
- Login failures
- Success messages
- Warnings or info messages


2. Enable flashing (requires secret key)
----------------------------------------
from flask import Flask, render_template, request, redirect, flash

app = Flask(__name__)
app.secret_key = "your_secret_key"   # Needed for flash messages


3. Flash an error message in your route
---------------------------------------
@app.post("/register")
def register():
    name = request.form.get("name")

    if not name:
        flash("Name is required!", "error")
        return redirect("/register")

    flash("Form submitted successfully!", "success")
    return redirect("/register")


4. Show flash messages inside HTML (register.html)
--------------------------------------------------
Place this block where you want messages to appear:

{% with messages = get_flashed_messages(with_categories=True) %}
  {% if messages %}
    {% for category, message in messages %}
      <div class="{{ category }}">
          {{ message }}
      </div>
    {% endfor %}
  {% endif %}
{% endwith %}


5. Optional: Style the messages with CSS
----------------------------------------
<style>
    .error {
        color: white;
        background: red;
        padding: 10px;
        margin: 10px 0;
    }
    .success {
        color: white;
        background: green;
        padding: 10px;
        margin: 10px 0;
    }
</style>


Flow Summary:
-------------
User submits form → Flask checks input → flash("message") → page redirects →
HTML displays the flashed message.
